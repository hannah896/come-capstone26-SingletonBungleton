# 중간보고서 (캡스톤 프로젝트: SingletonBungleton)

## 1. 요구사항 명세 기반 진행 현황

### 1.1 시스템 및 소프트웨어 아키텍처
본 프로젝트는 **Manager-Singleton 패턴**과 **HFSM(Hierarchical Finite State Machine)**을 결합한 유연한 아키텍처를 채택하였습니다.
- **중앙 관리 시스템**: `Main.cs`를 필두로 `GameManager`, `DataManager`, `SceneManagerEx`, `UIManager` 등이 모든 전역 상태를 제어합니다.
- **엔티티 관리**: `Player` 및 `Monster`는 HFSM 구조를 통해 복합적인 상태(Locomotion, Action, Attack 등)를 계층적으로 관리하여 코드 확장성을 확보했습니다.
- **데이터 기반 설계**: `ScriptableObject(SO)`를 활용하여 아이템, 레시피, 스테이지 데이터를 데이터베이스화하고, `UGS(Uni-Google-Sheets)`를 통해 실시간 밸런싱이 가능하도록 설계되었습니다.

### 1.2 기능별 상세 요구사항 구현 상태

### 1.3 UI/DB 및 테스트 설계
- **UI 프로토타입**: `UI_Hud_Game`을 통해 실시간 스탯(HP, Hunger, Sanity) 표시 기능을 구현했으며, 인벤토리와 제작창은 팝업 시스템으로 설계되어 중첩 사용이 가능합니다.
- **DB 설계**: 로컬 저장은 `JsonUtility`를 이용한 JSON 포맷을 사용하며, 클라우드 저장은 Firebase Realtime Database를 통해 사용자별 인벤토리 및 건축물 데이터를 동기화하도록 설계되었습니다.
- **테스트 계획**: `@@Test` 폴더 내 팀원별 전용 테스트 씬을 구축하여 기능 단위 테스트를 수행 중이며, `Unity Test Framework`를 도입하여 핵심 로직(아이템 스택, 데미지 공식)의 회귀 테스트를 준비 중입니다.

## 2. 추진 전략 및 문제 해결 결과

### 2.1 추진 전략 및 수행 방법
- **Git-Flow 전략**: `main`, `Dev`, `Feat/담당자` 브랜치를 엄격히 분리하여 병합 충돌을 최소화하고 코드 리뷰를 병행하고 있습니다.
- **기술 스택 고도화**: Unity 6의 최신 기능을 활용하기 위해 프로젝트 마이그레이션을 완료했으며, 비동기 처리를 위해 `UniTask`를 전면 도입하여 성능 최적화를 도모했습니다.

### 2.2 문제점 분석 및 해결 방안
#### 기술적 문제: 1인칭 시점 전환 시 카메라 클리핑 및 조작 이질감
- **문제점**: 초기 3인칭 기획에서 1인칭으로 전환하며 캐릭터 모델의 내부가 보이거나 조작이 딱딱해지는 문제 발생.
- **해결방안**: `Cinemachine`과 별도의 1인칭 전용 렌더링 레이어를 구축하고, `PlayerMotor`의 가속도 로직을 수정하여 부드러운 시점 전환 및 이동감을 확보함.

#### 일정 관리 문제: Unity 6 엔진 안정성 및 라이브러리 호환성
- **문제점**: 최신 엔진 버전 사용으로 인해 일부 기존 라이브러리(JSAM 등)에서 에러 발생 및 학습 곡선 존재.
- **해결방안**: 팀 내 기술 공유 세션을 통해 해결책을 기록(ADR)하고, 호환되지 않는 패키지는 직접 코드를 수정(JSAM Fix 커밋)하여 대응함.

### 2.3 팀원 역할 및 책임 수행 결과
- **조유진**: 시스템 아키텍처 설계, UI 프레임워크 구축, 플레이어 HFSM 로직 총괄.
- **김경보**: Photon Fusion 기반 멀티플레이어 동기화, Firebase 백엔드 연동.
- **박한나**: 절차적 월드 생성 알고리즘 구현, ScriptableObject 기반 데이터 구조 설계.

### 2.4 요구사항 변경 관리 결과
- **변경 사항**: 플레이어 시점 변경 (3인칭 → 1인칭)
- **관리 결과**: 1인칭 전환에 따라 근접 전투 판정 로직을 `Raycast` 및 `SphereCast` 기반으로 전면 재설계하였으며, 이에 따른 UI 인터페이스(HUD) 배치를 화면 중심에서 주변부로 재조정함.
